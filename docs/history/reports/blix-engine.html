The Engine, Counted

Every project that is Blix — what is inside each one, and who depends on it — read off the working tree rather than off the plans. Applications are set aside from the mass and kept in the graph, because a game tells you what Blix is for and not what it is. The point is granularity: at project level the engine looks like thirteen tidy modules, and at file level three of them are one subsystem each wearing a general name.

The demo band splits, and only half of it is excluded. Seven of the eleven demos are executable specs — the smallest call site that exercises a primitive, existing so the primitive has a known-good consumer. VulkanInstanced is 180 lines and its whole job is that 5,000 cubes go through one draw call. That is engine evidence and it counts. The other four grew into games with rules, scoring and a look of their own, and a game is a game regardless of which folder it sits in.

Labs are counted, and they are the one band I am not sure about. A lab is supposed to be temporary — allowed to be wrong, expected to be deleted. But Blix.Labs.Character is a 2,018-line library that three executables stand on, which is substrate-shaped rather than experiment-shaped, and the last lab that stopped being fuzzy turned out to be Blix.Tools.Studio under a misleading name. Until that is settled they count, and 6.5% is small enough that the answer does not move the picture either way.

Applications are excluded from the mass, not from the graph. Fan-in throughout the rest of this page still counts all 45 projects — a module is load-bearing precisely because a game depends on it.

What the bands then say is that Blix is an engine with a small amount of everything else around it. Nine tool projects average 852 lines against the engine's thirteen at 2,691, so "a project" means two different sizes of thing depending on the band — and the tools band is where adding one is arithmetically cheap. Whether it is actually cheap is the question the rest of this page and its companions are about.

Counted with find … -name "*.cs" excluding bin/ and obj/; blank lines and comment lines included, because in this tree the comments are a substantial and deliberate part of what a file is. Shaders, scripts and assets are not counted. The spec/game split among the demos is a judgement call and the two lists are given above so it can be disputed — VulkanLit and VulkanSponza are the two I would argue about, and both are counted as specs because neither has rules or a player.

The tier that matters most is the first. Three projects reference nothing at all, and in every case that is the design rather than an accident. Blix.Verify is a test tally that must not depend on what it counts. Blix.Tools.Apps reads assembly metadata without loading assemblies, so it must not reference the graph it indexes. Blix.Cli resolves and execs apps, and an app must not be able to tell it exists.

A fourth, Blix.Graphics, has no references either — but it is referenced by thirty, which makes it a different kind of thing: a root, not an island.

05 — what the counting found

Five things that are only visible at this granularity

Three importers in Blix.Assets have no callers.

Searched across every .cs in src/. FontImporter is the only IAssetImporter anything ever registers — glTF, textures and audio all bypass the database entirely and call their loaders directly.

MaterialImporter 195 lines — 0 callers
WavImporter 134 lines — 0 callers
TextureImporter 13 lines — 0 callers

The asset database exists to route one font.

Four projects call LoadManifest. All four manifests contain exactly one entry, and it is the same TTF. AssetDatabase + AssetId + IAssetImporter + the manifest schema is 209 lines serving one file type.

Runner, Bulwark, Pong → fonts/bowlby · RTSGame → fonts/hud
same source: BowlbyOne-Regular.font.json

The two viewer projects outweigh most of the engine, one module at a time.

Blix.Tools.Studio at 2,261 is larger than seven of the thirteen engine projects; Blix.Tools.View at 1,741 is larger than five. With the applications set aside the band is 13.1% of Blix against the engine's 59.7% — so the tooling is not a thin layer any more, it is a peer of the modules it sits on, and two of its nine projects are half of it.

tools 7,668 across 9 (13.1%) · engine 34,981 across 13 (59.7%)
the two viewers alone: 4,002 — and 944 more in Shot showing the same two assets

The verification band is 6,045 lines and 84% of it is two suites.

Blix.Test.Graphics (3,338) and Blix.Test.Diagnostics (1,758) carry almost all of it, each as a single file. The four small suites average 205 lines, which is the size at which adding one is a cheap decision — and Blix.Verify, the shared tally that made that true, is 129 lines with zero references.

Graphics 3,338 · Diagnostics 1,758 · Physics3D 252 · Physics2D 230 · Studio 194 · Apps 144 · Verify 129

Ten of the eleven demos depend on Blix.Tools.Shader.

Fifteen projects reference it — a 144-line build-time tool — because compiling GLSL is part of being an application here, not part of being a tool. It is the clearest case in the tree of something named Tools. that is actually engine-side, and the naming has never been corrected because nothing has gone wrong because of it. The eleventh demo, Chassis, is the exception precisely because it draws nothing of its own.

Five application projects are excluded from every line total on this page — RTSGame, Pong, Runner, TankArena and Bulwark, 77,106 lines between them — on the grounds that they are what Blix is for rather than what it is. They are not excluded from fan-in, which still counts all 45 projects: a module is load-bearing because applications depend on it, and removing them from the graph would misreport exactly the thing fan-in is for. docs/blix-topology.html counts the whole tree including them. Fan-in is ProjectReference declarations only — it does not count using, so a project that references another and uses one type counts the same as one that uses forty. Subsystem groupings inside Blix, Blix.Graphics.Vulkan and Blix.Graphics are a judgement call, made by file name; the file lists are given so the grouping can be disputed.
